# Project traps

- **Do not read the saved password just to prefill an email field, or rewrite unchanged credentials after automatic login.** The native window's `onAppear` previously called `Keychain.load` in addition to the client's startup read; automatic login then called `Keychain.save` again. Each unnecessary operation could request macOS Keychain authorization. Keep the email in client memory and save only after a successful manual login (`MyJDownloader/AppDelegate.swift`). This removes duplicate access without broadening the item's access rules; a user's system authorization request after a changed ad-hoc build remains a separate concern. The initial report was clarified as one authorization for a local build and another for the Brew build. After the user chose Always Allow, a controlled restart of the unchanged v1.1.0 app at 08:02:30 on 2026-09-08 produced no prompt and connected automatically (user-confirmed). This disproved a persistent same-build startup-prompt defect in that run. The redundant-call cleanup is preventive, not the proven cause of those two prompts; do not broaden ACLs or claim updates preserve the same authorization. The verified Brew installation remains unchanged.

- **Use exactly one jdapi constructor handshake per native login and isolate each login in a fresh nonpersistent WebView.** The bundled `JDAPICore` constructor calls `connect` itself and maintains module-global API state. Constructing it with a configuration-shaped object and then calling `connect(credentials)` races two handshakes; merely hiding the native UI on logout leaves outstanding callbacks and JS session state alive. The bridge passes credentials plus a Deferred to the constructor, rejects messages from replaced WebViews, times out native requests, and prevents Keychain auto-login after logout even if credential deletion fails (`MyJDownloader/AppDelegate.swift`, `vendor/jdclient.html`, `vendor/jdclient.js`, `vendor/js/jdapi.js`). Separate native/Safari logins are retained; shared-session work was rejected for this fix because it adds a new cross-process credential contract. Costs: rebuilding a small WebView per login; benefit: old account callbacks cannot restore the new account's UI state. Regression tests cover the constructor and stale JS responses; real account/browser acceptance is a separate gate. A review hypothesis that logout permanently leaves `polling` true was disproved: `resetSession` assigns `selectedDeviceId = nil`, its `didSet` resets `polling`, and a Swift runtime check confirmed that nil-to-nil assignment still invokes the observer. A temporary automatic-login failure must not persist the explicit-logout suppression flag; `connect(automatically:)` distinguishes these cases.

- **Never auto-select an Apple Development certificate when installing the personal Homebrew cask; verify every signing step and keep a certificate-free default.** On 2026-09-08 the first identity was revoked (`CSSMERR_TP_CERT_REVOKED`), a second identity had the same display name, and the installed app was rejected by `amfid` before `syspolicyd` moved it to Trash. The checksum-matching original v1.0.2 archive had a valid ad-hoc signature; re-signing a test copy with the second identity verified successfully. Preserving requirements also verified with the valid identity, disproving stale requirements as the cause. A successful `codesign --sign` alone does not establish certificate validity. Affects `traktuner/homebrew-tap:Casks/j/jdownloader2-safari.rb` and the CI-to-cask installation contract. Evidence: `/tmp/myjd-review-j1eo_zv1/{release,signature-preserved,signature-fresh,second-preserved,second-fresh}`; repository base `main@0ca78fe5614b6aacd69df1b7fa2a66f2ad9f5fef`. Onyx search/write tools unavailable in the 2026-09-08 session; shared documentation remains pending.

- **Never persist an unfinished popup password in `chrome.storage.local`, even with an expiry timestamp.** The previous draft implementation only removed expired data when the popup reopened, leaving plaintext on disk indefinitely otherwise. Store drafts in the background page's memory, expire them actively, restrict reads to extension login pages, and remove the old key without reading its value (`PopupController.js`, `BackgroundController.js`, `BackgroundScriptService.js`).

- **Never send Click'n'Load through `CACHED_DEVICE_LIST` without first refreshing the live jdapi device list.** Safari can restore the MyJDownloader session and cached preferred device before jdapi has populated its in-memory device controller, causing the first `/linkgrabberv2/addLinks` call to fail with `DEVICE_NOT_EXISTING`; do not return a synthetic CnL `success` before that asynchronous call completes (`BackgroundController.js`, `cnlCaptureContentscript.js`).

- **Do not treat an inline page-world hook or a spoofed jdownloader global as universal Click’n’Load compatibility.** Strict HTTP CSP blocked the baseline scripted fetch capture in a real WKWebView fixture; an isolated-world DOM submit listener handled the strict-CSP form fixture. Keep that listener in capture phase so page stopPropagation does not hide submissions, deduplicate page/isolated listeners, and render acknowledgment without replacing the cryptor document (`MyJDownloader Extension/Resources/contentscripts/cnlCaptureContentscript.js`). The retained inline hook still cannot guarantee script-only fetch/XHR or programmatic form.submit under strict CSP. A WKUserScript page-world experiment is not evidence of an available Safari extension MAIN-world API, so no unverified scripting API was shipped. The early missing-document-root hypothesis was not established by the runtime fixture; MutationObserver retry is defensive only. Node fixtures must separate page and extension globals; real WebKit fixtures must install network stubs before capture hooks. Evidence: `/Users/thomas/Developer/builds/myjd-safari/chrome-comparison/webkit-fixtures/result-3.log`, baseline `main@cab6be507c9a1b217dedd32a01b57f6b25b25522`; compatibility limits in `docs/CNL-COMPATIBILITY.md`. Actual Chrome-package comparison and live cryptor/device acceptance remain open. Onyx search/write tools were unavailable; this is the local fallback, shared persistence remains blocked.

- **Do not treat PlugInKit registration or local ad-hoc signing as a durable Safari installation.** Safari 17 and later reset “Allow unsigned extensions” every time Safari quits; with that setting off, Safari hides the otherwise valid and registered `org.myjdownloader.MyJDownloader.Extension`. On 2026-09-09 Safari 26.6.2 showed no MyJDownloader entry while `pluginkit -mAvvv -p com.apple.Safari.web-extension` listed the embedded extension and `codesign --verify --deep --strict` passed. The Developer setting was visibly off, establishing the distribution signature as the failure boundary. A reliable Homebrew/bare-metal release must preserve a Developer ID signature and Apple notarization for the containing app and embedded appex; the cask must verify that release and must not ad-hoc re-sign it, because doing so replaces the distributable signature. A local Apple Development or Apple Distribution identity is not a Developer ID Application identity. Affected paths: `.github/workflows/build.yml`, `scripts/build.sh`, and `traktuner/homebrew-tap:Casks/j/jdownloader2-safari.rb`. Apple’s distribution guidance confirms Developer ID signing and notarization for Safari web extensions distributed outside the Mac App Store. Onyx search/write tools were unavailable; this local trap is the fallback and shared persistence remains blocked.

- **Never let a blocking Click'n'Load `webRequest` listener fall back to an observer in Safari.** Safari rejects `["requestBody","blocking"]`; the old `safeAddWebRequestListener` then re-registered `interceptRequest` as a plain observer. Its side effects still ran on every `127.0.0.1:9666/flash/*` request: `handleCnlNewTab` removed the cryptor tab and `flashAddCrypted` queued a toolbar without the request body, while the real request went to the page hook or the native port. Register CnL with `observerFallback=false`; only `Rc2Service.handleRequest` may observe (`MyJDownloader Extension/Resources/scripts/controllers/BackgroundController.js`). Native Click'n'Load lives in the app (`MyJDownloader/AppDelegate.swift`, `ClickNLoadServer`, loopback 127.0.0.1:9666 only, needs `ENABLE_INCOMING_NETWORK_CONNECTIONS`); the extension answers `{passthrough:true}` when logged out or CnL is off so the page sends the original request there. The original Chrome 3.3.20 package is at `../../extension` and `../../myjd.crx`; the 2026-09-08 claim that it was unavailable was wrong.

- **Strip only `com.apple.security.get-task-allow` after a Developer ID `xcodebuild build`; never set `CODE_SIGN_INJECT_BASE_ENTITLEMENTS=NO`.** The project has no `.entitlements` files: sandbox/network entitlements come from `ENABLE_APP_SANDBOX`/`ENABLE_*_NETWORK_CONNECTIONS` via base-entitlement injection, and a plain `build` (not archive/export) also injects `get-task-allow=true` even in Release. Notarization of v1.2.0 (submission 988a3694-9f12-4d27-9de1-43680d46f1b5, run 38683938869) returned `Invalid` for that reason; disabling injection removed every entitlement including the sandbox Safari requires. `scripts/release.sh` re-signs appex then app with the extracted entitlements minus that key and fails if the sandbox is missing or the key remains.

- **Never re-inject manifest content scripts into a Safari tab without probing first.** `injectContentScripts()` (startup, login, onInstalled) exists because Chrome does not run content scripts in tabs opened before install; Safari already does, so the second `executeScript` landed in the same content-script world and threw `SyntaxError: Can't create duplicate variable: 'intermediateBody'` (top-level `const` in `rc2Contentscript.js`), shown as an extension error in Safari after v1.2.1 installed via Brew. It would also add a second Click'n'Load relay listener (double link delivery). Probe a top-level binding first (`typeof CaptchaFormInjector`, `typeof BrowserSolverEnhancer`) and skip the tab when it exists (`BackgroundController.js`, `Rc2Service.js`).
